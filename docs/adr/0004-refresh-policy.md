# Weekly CI refresh for açudes and rain only; every other layer frozen with a source year

Status: accepted (2026-09-03)

## Context

Reservoir volumes move weekly and rainfall daily. Census, geology, crime and school data change yearly or slower. The site is static (ADR 0001), so any refresh has to be a commit.

## Decision

- A GitHub Actions cron runs weekly: read ANA's SAR for reservoir volumes, append to the history JSON, commit, redeploy.
- On scrape failure the job fails loudly and commits nothing. The layer card shows the last successful date as "dados de <data>"; the badge turns amber past 14 days.
- Reservoir history is seeded once from SAR, which carries daily readings back to 2013, then appended weekly. The seeded series is what makes a drought-history view possible, not just a current snapshot.
- All other layers are regenerated by hand when an agency publishes a new release. The manifest carries the year per layer and the card shows it.
- Missing values render as hatched "sem dados", are excluded from ranks and aggregates, and the number of municípios with data (n) is shown next to every rank.

Rain-gauge readings have no public source: AESA gates them behind the same authentication as its reservoir volumes. The gauge layer shows where measurement happens and is not refreshed.

## Consequences

- The repo grows by one small JSON delta per week.
- A SAR markup change breaks the job visibly instead of silently serving stale or wrong numbers, since the readings are parsed out of an HTML table rather than a versioned API.
- Nothing is fetched live in the browser.
